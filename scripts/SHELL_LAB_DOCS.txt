================================================================================
VAMPSECURE INTELLIGENCE - AARCH64 SHELL-LAB v1.4 (M3 EDITION)
================================================================================

DESCRIPCIÓN:
Módulo de ejecución de código nativo de bajo nivel diseñado para arquitecturas 
ARM64 (Apple Silicon). Permite la inyección y ejecución de instrucciones 
directamente en los registros del procesador, saltando las capas de abstracción
del sistema operativo.

CARACTERÍSTICAS TÉCNICAS:
- Arquitectura: ARM64 / AArch64.
- Método: Inline Assembly (Ensamblador en línea) para precisión de offset.
- Syscalls: Uso directo de la tabla de llamadas al sistema Linux-ARM64.
- Optimizaciones M3: Alineación de memoria a 4 bytes y gestión de I-Cache.

ESTRUCTURA DE REGISTROS UTILIZADA:
- x0: Descriptor de archivo (stdout = 1) / Status de salida.
- x1: Puntero de memoria a la carga útil (Buffer).
- x2: Longitud de la carga útil.
- x8: ID de la Syscall (64 para write, 93 para exit).

USO Y COMPILACIÓN:
Ruta: scripts/shell_lab/vamp_shell_lab.c

1. Compilación:
   docker exec -it vamp_python_lab gcc -o scripts/shell_lab/vamp_shell_lab \
   scripts/shell_lab/vamp_shell_lab.c

2. Ejecución:
   docker exec -it vamp_python_lab ./scripts/shell_lab/vamp_shell_lab

PRUEBA DE CONCEPTO (PoC):
El binario ejecuta un salto de ejecución al Program Counter (PC) hacia una 
etiqueta de memoria dinámica. Si la terminal devuelve la cadena "VAMP", se 
confirma la ejecución exitosa de código arbitrario en memoria protegida.

================================================================================
ANEXO TÉCNICO: ARQUITECTURA ARM64 Y MEMORIA EN APPLE SILICON
================================================================================

El procesador M3 utiliza una arquitectura RISC (Reduced Instruction Set Computer)
que impone restricciones que no existen en arquitecturas x86 (Intel).

1. ALINEACIÓN DE INSTRUCCIONES (Instruction Alignment)
En ARM64, cada instrucción DEBE medir exactamente 32 bits (4 bytes). Si el 
código no está alineado, el procesador genera un "Alignment Fault". 
VampSecure soluciona esto mediante la directiva:
   .align 2 (Alineación a 2^2 = 4 bytes)

2. COHERENCIA DE CACHÉ (Harvard Architecture)
Los chips M3 tienen cachés separadas para Datos (D-Cache) e Instrucciones (I-Cache). 
Al escribir shellcode, lo hacemos como DATOS, pero al ejecutarlo, la CPU lo 
busca en INSTRUCCIONES.
Fórmula de sincronización:
   D-Cache Write -> Flush to RAM -> I-Cache Invalidate -> I-Cache Fetch

3. DIRECCIONAMIENTO RELATIVO (ADR Instruction)
A diferencia de x86, ARM64 prefiere el direccionamiento relativo al PC. 
La instrucción 'adr x1, msg' calcula la posición del mensaje sumando un 
desplazamiento (offset) a la posición actual del Program Counter (PC).

$$Dirección_{destino} = PC + Offset_{calculado}$$

Esta técnica permite que el shellcode sea "Position Independent" (PIC), 
pudiendo ejecutarse desde cualquier lugar de la memoria RAM.

================================================================================
GUÍA DE CONFIGURACIÓN DOCKER PARA APPLE SILICON (M3)
================================================================================

Para que las herramientas de bajo nivel como el Shell-Lab funcionen en un Mac M3,
el archivo docker-compose.yaml debe estar configurado para permitir la 
transmutación de permisos de memoria.

CONFIGURACIÓN RECOMENDADA:
--------------------------------------------------------------------------------
services:
  python-tester:
    image: vampsecure_lab-python-tester
    platform: linux/arm64/v8  <-- Asegura compatibilidad nativa con M3
    cap_add:
      - NET_ADMIN             <-- Necesario para ICMP Tunnel
      - SYS_PTRACE            <-- Necesario para Debugging de procesos
    security_opt:
      - seccomp:unconfined    <-- Permite mprotect() y ejecución de shellcode
    volumes:
      - .:/app
--------------------------------------------------------------------------------

NOTA SOBRE RENDIMIENTO:
Al ser arquitectura nativa ARM64, el código ejecutado en el contenedor tiene 
un overhead casi nulo, permitiendo pruebas de estrés de shellcode idénticas a 
un entorno bare-metal.
